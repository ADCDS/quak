# Quakが変更するもの、保存するもの、削除できるもの

Quakは実物のカメラを操作し、コンピューターのWi-Fiに手を加えることがあります。このページでは、Quakが何をするのかを正確に説明します。

## コンピューターについて

**Bluetooth:** QuakはシステムのBluetoothを通じて、通常の方法でカメラとペアリングします。それ以外は何も変更しません。

**Wi-Fi:** プレビュー、メディア、ダウンロードには、カメラ自体のWi-Fiネットワークが必要です。

- **スマートフォン:** Androidはアプリのためだけに接続し、他のアプリは通常のネットワークのままです。
- **コンピューター:** Wi-Fiアダプターがしばらくカメラのネットワークに接続し、Quakの処理が終わるまで、それまで接続していたネットワークから離れます。

コンピューターでは、Quakは次のように動作します。

- インターネット接続に使っていないアダプターを優先します。使用中のアダプターしかない場合、アプリは先に確認し、コマンドラインは`--wifi-adapter NAME`で選択するまでエラーで停止します。
- Linuxでは、`quak-camap`という名前の一時的なNetworkManagerプロファイルを作成します。このプロファイルがデフォルトルートやDNSを奪うことは決してなく、使用後に削除されます。他のプロファイルは編集しません。
- Linuxでは、使用中はそのアダプターの自動接続をオフにします。そうしないと、カメラ用の保存済みプロファイルがアダプターを奪い返す可能性があるためです。自動接続は使用後に元に戻します。
- 処理が終わると、以前のネットワークに再接続します。アプリでは、メディア画面を離れるかプレビューを停止してから約1分後に再接続します。

### Quakが強制終了された場合

コマンドラインはCtrl-Cと`kill`で後片付けを行い、変更した内容を元に戻します。さらに強制的に終了された場合や、使用中にマシンの電源が落ちた場合は、Quakが変更内容を記憶しており、Linuxでは次回の起動時に元に戻します。Windowsには自動復旧はありません。

Linuxで手動で復旧するには、次を実行します(`DEVICE`はお使いのWi-Fiアダプターです)。

```bash
nmcli connection delete quak-camap
nmcli device set DEVICE autoconnect yes
nmcli device connect DEVICE
```

再起動でも自動接続の変更は解消され、削除が必要なものは`quak-camap`プロファイルだけになります。

### 保存されるもの

| 対象 | 場所 | 内容 |
|---|---|---|
| ペアリング済みのカメラ、設定 | Linuxでは`~/.config/quak`、Windowsでは`%APPDATA%\quak`、Androidではアプリのプライベートストレージ | カメラのアドレス、モデル、アプリの設定 |
| ダウンロード | デスクトップアプリでは`~/Videos/Quak`、Androidではアプリのプライベートストレージ、コマンドラインでは`--out`または現在のフォルダー | お使いのクリップ |
| テストデータ | Linuxでは`~/.local/state/quak`、Windowsでは`%LOCALAPPDATA%\quak` | テストスイートを実行した場合のみ |

QuakはWi-Fiのパスワードやストリームキーを保存しません。ネットワークへの接続や配信を指示したときに、カメラへ送信します。

### ログの内容

診断画面、そこからエクスポートしたログ、および`quak -v`には、カメラとやり取りしたバイト列が表示されます。パスワード、ストリームキー、ネットワーク名、カメラのシリアル番号、コンピューターの名前は除外され、隠されたバイト数が示されます。

カメラのBluetoothアドレスはエラーメッセージやログに残る場合があるため、ログを公開で共有する前に内容を確認してください。

### アプリのネットワークアクセス

`quak-gui --web`は、このコンピューター上でのみ、ブラウザーにアプリを提供します。**ログインはなく**、アクセスできる人は誰でも、カメラでの録画やカメラからの削除を実行できます。そのため、`--host`が意味を持つのは、完全に信頼できるネットワーク上だけです。

## カメラについて

ペアリング時に、**Quakはコンピューターの名前をカメラに伝えます**。これは、カメラがこのデバイスの名前として表示するものです。

**スケジュールキャプチャーは設定を変更し、変更したままにします。** 予約すると、次のことが行われます。

- カメラをプロコントロールに切り替えます(カメラはイージーではスケジュールキャプチャーを表示しないためです)
- 選択したビデオプリセットを読み込みます
- ビデオの撮影時間を設定します。これは**手動で開始する録画も制限します**
- カメラの時計を同期します

予約によってこれらが変更されると、Quakが通知します。終わったら、カメラの設定またはQuakで撮影時間を元に戻してください。

**ライブ配信:**

- カメラは選択したWi-Fiネットワークに接続し、そのネットワークを保存します。保存されたネットワークを削除できるのは、カメラの**接続をリセット**(Reset Connections)だけで、これを行うとカメラのすべてのペアリングも削除されます。
- ネットワークのパスワードと、ストリームキーを含むストリームURLは、Bluetooth経由でカメラに送信されます。
- 通常の`rtmp://` URLでは、ストリームキーと映像は暗号化されずにサーバーへ送られます。

**カメラのWi-Fi**は必要なときにオンになり、Quakがオンにした場合は、Quakの処理が終わるとオフに戻ります。プレビュー中に強制終了されたアプリは、Wi-Fiをオンのままにすることがあります。その場合は`quak ap off`を実行するか、カメラでオフにしてください。

## Quakが削除できるもの

選択したクリップだけです。削除するときは、アプリでは必ず確認が表示され、コマンドラインでは`--yes`が必要です。削除したクリップは復元できません。

Quakには、カードのフォーマット、すべての削除、カメラの工場出荷時リセットを行う手段はありません。

ダウンロードが既存のファイルを置き換えることはありません。2つ目の`GX010001.MP4`は`GX010001_1.MP4`として保存されます。途中で切断されたダウンロードはエラーとして報告され、完了したものとして保存されることはありません。

## 開発者向け

`QUAK_DEV=1`を指定すると、アプリのセルフテストとライブ画面のテストモードが表示されます。これらははるかに多くのものを変更するため、先に[testing.md](https://github.com/ADCDS/quak/blob/main/docs/testing.md)をお読みください。

- **セルフテスト:** 約30分かかり、クリップを録画し、設定を変更して元に戻し、Wi-Fiアダプターを使用します。
- **テストモード:** このコンピューターをホットスポットにし、カメラはそのネットワークを保存します。
