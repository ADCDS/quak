# トラブルシューティング

## ペアリングと接続

**「No camera is on its pairing screen」と表示される。** カメラは、**ユーザー設定 > ワイヤレス接続 > デバイスを接続 > GoPro Quikアプリ(Preferences > Connections > Connect Device > GoPro Quik App)** の画面が開いていない限り、登録されていないデバイスを無視します。この画面を開いてから、もう一度`quak pair`を実行してください。

**スマートフォンの次にコンピューターをペアリングすると失敗する。** 別のデバイスから接続すると、カメラのペアリング画面が閉じます。ペアリングは1台ずつ行い、次のデバイスをペアリングする前に画面を開き直してください。

**「45秒以内に見つかりませんでした」(not seen within 45 s)と表示される。** カメラの電源が入っていて、近くにあることを確認してください。ペアリング中でないとき、HERO11のアドバタイズは10〜20秒に1回程度まで少なくなることがあり、スリープ中のカメラではさらに時間がかかる場合があります。もう一度試すか、カメラのボタンを押してスリープから復帰させてください。

**接続はするが、セットアップが完了しない。** 以前、USB接続中にカメラの電源が落ちた後、再起動するまでBluetoothサービスを提供しなくなったことが一度ありました。カメラの電源を切ってから入れ直してください。

**カメラが理由を示さずに録画や設定変更を拒否する。** ターボ転送(Turbo Transfer)モードのままになっている可能性があります。このモードでは録画、設定、プレビューがブロックされます。Quakはダウンロード時にこのモードをオンにするため、ダウンロード中に接続が切れるとオンのままになることがあります。アプリは次回の接続時に解除します。コマンドラインではエラーメッセージにその旨が表示されるので、`quak turbo off`を実行してください。

## Bluetoothのエラー

**「Bluetoothが応答しなくなりました」(Bluetooth stopped responding)と表示される。** Bluetoothがオンになっていることを確認してください。Linuxで繰り返し発生する場合は、カーネルログを確認してください。

```bash
journalctl -k | grep "tx timeout"
```

`command 0x2041 tx timeout`のような行の後にUSBの切断が続いている場合は、Bluetoothアダプターがクラッシュしています。Quakではこれを防げません。あるUSB Bluetooth 5.4ドングルでは、ポートを変えても、他に何も使っていなくても、1日に20回以上発生しました。アダプターはオフの状態で復帰するので、`bluetoothctl power on`でオンにしてください。頻繁に発生する場合は、別のアダプターを試してください。

**アダプターのクラッシュ後に「45秒以内に見つかりませんでした」(Not seen within 45 s)と表示される。** 同じドングルが、オンであると報告しながら何も受信していない状態で復帰することがあり、ログにエラーは出ませんでした。カメラの電源が入っていて、近くの他のデバイスもBluetoothスキャンに表示されない場合は、Bluetoothをオフにしてからオンに戻してください。`bluetoothctl power off`の次に`bluetoothctl power on`を実行します。

## Wi-Fi、メディア、プレビュー

**「Wi-FiアダプターXはこのコンピューターのネットワーク接続に使われています」(Wi-Fi adapter X is this computer's network connection)と表示される。** Quakは確認なしに接続を奪うことはありません。2つ目のアダプターを接続するか、`--wifi-adapter X`で許可してください。アプリでは代わりに確認が表示されます。

**スマートフォンで「カメラのWi-Fiに接続中」(Joining the camera's Wi-Fi)に時間がかかる。** カメラのWi-Fiがオフだった場合、スマートフォンがそれを検出するまでに30秒以上かかることがあります。

**スマートフォンに接続できなかったと表示され、「接続の確認を拒否しましたか？」(was the Connect prompt declined?)と出る。** Androidはカメラのネットワークに接続する前に一度確認を求めます。確認が表示されなかった場合は、もう一度試してください。スマートフォンが時間内にネットワークを見つけられなかったという意味の場合もあります。

**プレビューに何も表示されない。** カメラは録画中にストリームを停止します。パネルにその旨が表示されるのはそのためです。録画を停止した後やモードを変更した後は、約10秒以内にストリームが戻り、約20秒以内に映像が表示されます。

**「カメラがプレビューを開始しませんでした」(The camera didn't start its preview)と表示される。** カメラが拒否しました。しばらくしてからもう一度お試しください。強制終了されたアプリが残したストリームは、Quakがすでに解除しています。

**「カメラから映像が届きませんでした」(No picture came from the camera)と表示される。** Quakはプレビューを開始しましたが、30秒以内に映像が届きませんでした。もう一度お試しください。コンピューターで繰り返し発生する場合は、カメラが映像を送信するUDPポート8554への受信をファイアウォールが許可していることを確認してください。

**カメラのWi-Fiがオンのままになる。** プレビュー中に強制終了されたアプリはWi-Fiをオフにできません。`quak ap off`を実行してください。

**Quakが強制終了された後、コンピューターのWi-Fiが切れた。** [Quakが強制終了された場合](safety.md#quakが強制終了された場合)をご覧ください。

## アプリ

**`quak-gui`でディスプレイがないと表示される。** SSH経由など、画面のないマシンを使用しています。`quak-gui --web`を使うと、同じマシンのブラウザーにアプリを提供します。

**初回起動が止まったように見える。** デスクトップクライアントは約45 MBあり、ダウンロードは一度だけです。

**Androidアプリを更新できない。** 異なる鍵で署名されたAPK同士は互いに更新できません。先に古いものをアンインストールしてください。アンインストールすると、そのペアリング情報とダウンロードしたファイルは削除されます。

## 既知の問題

**ネットワークへの接続時にライブ配信が止まることがある(実験的)。** カメラはWi-Fiネットワークに接続してハンドシェイクを完了しますが、IPアドレスを要求しないため、60秒後に接続がタイムアウトします。テスト用カメラではライブ配信がエンドツーエンドで動作しており、この問題が始まった日にも2回動作しましたが、その後の試行はすべて止まりました。該当するカメラでの結果は次のとおりです。

| 試したこと | 結果 |
|---|---|
| カメラのスリープと復帰 | 止まったまま |
| カメラの再起動 | 止まったまま |
| コンピューターのWi-Fiアダプターの差し直し | 止まったまま |
| カメラが一度も見たことのないネットワーク名 | 止まったまま |
| スマートフォンで同じネットワークに接続 | 動作する |

ネットワーク自体に問題はないため、応答がないのはカメラ側です。原因も、Quakが送信した内容が原因かどうかもわかっていません。カメラの**接続をリセット**(Reset Connections)は、すべてのペアリングも削除されるため、まだ試していません。この問題に遭遇した場合や解決できた場合は、[Issueを作成](https://github.com/ADCDS/quak/issues)してください。

**タップが反応しないことがまれにある。** 一部の画面は、カメラが変更を報告すると全体が再描画され、その瞬間のタップは失われます。もう一度タップしてください。メディア画面と診断画面では、この問題はなくなりました。

**Windowsはカメラで実行したことがありません。** 実験的なものなので、気づいたことをぜひご報告ください。
